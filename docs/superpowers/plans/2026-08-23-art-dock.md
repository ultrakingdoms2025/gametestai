## Task 1 — baseline, before touching anything

`node scripts/world-shot.mjs --world dock --out .probe/art-dock/before`

24 framings. Recorded with `gameplayDriven: true` and a hardware GL string, because a run
that lost either is a run whose numbers mean nothing.

**Done when** `report.json` exists and the table is in the spec.

## Task 2 — make the harness usable on this world

The yard published one material name in total, so `--ablate` had nothing to hide and
`materialNames` reported the constructor census. `buildYardMaterials` now names every material
`yard.<key>`; `mat.emPier`, declared outside it, names itself.

This is a prerequisite, not a nicety: without it the only tool that can answer "which system
drew this pixel" cannot be pointed at anything here.

**Done when** a report's `materialNames` reads yard keys, and `yard-assets.test.mjs` holds the
name to the key.

## Task 3 — judge the shots, and measure rather than adjective

Frame statistics off the committed PNGs: mean luma, mean saturation, clipped %, dark %.

Outcome (spec §2):

- **`trench` is not a blow-out.** 0.00% clipped in all 24 framings. The bloom hypothesis was
  wrong; nothing was changed for it. Recorded as a dead end.
- **The hull sections are the defect.** 39.1 luma / 0.193 sat / 85% under 48/255 on a nine-metre
  drum.
- **The keel line is the other one.** 1.6× the frame's saturation on the first framing a player
  ever sees, against the world's own written colour rule.
- **The white blobs are `Loot.js`.** Already diagnosed by `art-medieval`, shared by nine
  worlds, out of boundary. Not touched.

## Task 4 — the authored `.glb` (D4)

The route proven four times, in the order it was proven, changed in nothing.

1. **`scripts/make-yard-glb.mjs`** — a committed generator.
   - `SECTIONS` **imported** from `dock/YardPlan.js`, so a plan edit turns the byte-diff red
     instead of letting the asset drift.
   - Exports `TRI_BUDGET`, `SECTION_PARTS`, `YARD_PART_KEYS` so a test can assert the
     generator, the loader and the manifest have not drifted apart.
   - `YARD_GLB_SECTION` / `YARD_GLB_OUT` env overrides, so the byte-diff test can re-run it
     into a temp file. A generator that can only write its committed path cannot be tested.
   - A NaN gate on positions, normals and uvs — `make-ship-glb` paid for that one with a white
     screen.
   - **A winding gate**: `quad(…, expect)` throws when a face points away from the direction it
     is supposed to be seen from. It caught the cut-end collar and the bulkhead on its first
     run, and rejected a bad "correction" to the plate laps on its second.
   - Placeholder glTF materials so the file opens in a viewer, and a test asserting the game
     never reads them.
2. **`public/assets/dock/manifest.json`** — id, file, kind, licence, source, parts, tris,
   bytes, plus `sections`.
3. **`src/worlds/dock/YardAssets.js`** — the lazy loader. A near-copy of
   `medieval/BeastAssets.js` **by intent**: manifest, lazy `GLTFLoader`, parallel fetches with
   an abort signal, per-asset `try`/`catch`, one warning per distinct failure, a synchronous
   cache read returning null rather than throwing, `BASE_URL` not `/`, and an
   `installYardAssets` seam so `node --test` can drive the real batch path with the real
   committed bytes.
4. **`DockWorld`** — `loadYardAssets()` started alongside `loadShipAssets()` so the two fetches
   overlap, awaited before `_buildSections`. `_buildSections` keeps both arms on the same `cy`,
   the same `_solidRot` collider and the same batch keys, re-checks each part key against the
   live `this.mat`, and **clones** every geometry because `GeoBatch` takes ownership.
5. **`docs/assets/LICENCES.md`** — one line per asset.
6. **`scripts/tests/yard-assets.test.mjs`** — 22 cases: provenance, byte-diff, both directions
   of every cross-reference, the collider-fit gate, and two builds of the real world compared
   mesh-for-mesh and material-for-material.

One constant, `KEEL_PAINT`, used by both places the line is struck. Saturation 0.469 → 0.171,

## Task 6 — re-shoot and diff

`node scripts/world-shot.mjs --world dock --out .probe/art-dock/after --compare .probe/art-dock/before`

Same 24 framings, same order — **the order matters**: `programs` is a live read of
`renderer.info.programs.length`, which is a cumulative cache, so it is only comparable
view-for-view against a run that visited the same views in the same sequence.

`npm test`, `node scripts/contract-check.mjs`, `npm run build`. Before/after JPEGs committed to

## Dead ends, recorded so they are not retried

- **"The trench is a bloom blow-out."** It is not. 0.00% of pixels clip in any framing. It is
  warm and hazy by design and the numbers say leave it alone. Two systems were nearly changed
  on the strength of one screenshot read.
- **"The plate laps are wound backwards."** They were not; the collar and the bulkhead were.
  Re-deriving three cross products in a comment "fixed" twenty-four correct quads. The winding
  gate rejected it on the next run, which is the only reason it did not ship.
- **"The authored sections will cost triangles."** They cost **fewer**: six smooth
  `TorusGeometry` frames per section were spending more geometry than the entire authored
  build. See the budget table in the spec.
